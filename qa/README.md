# qa/ — 회귀 검증 하네스 (QA 소유)

> ⚠️ **개발자는 이 폴더의 파일을 고치지 않는다.** 소유자는 윤진(QA)이다.
> 검사가 실패하면 이 폴더가 아니라 `app/`·`components/` 를 고친다.

## 왜 별도 폴더인가

`lib/__tests__/` 의 테스트는 **구현된 동작**(코어 배선 스모크)을 기술한다.
이 폴더는 **요구된 동작** — "사용자가 눌렀을 때 화면이 실제로 바뀌는가" — 를 기술한다.

그래서 vitest 설정도 분리돼 있다. `vitest.config.ts` 는 `lib/**/*.test.ts` 만 보고,
이 폴더는 `vitest.qa.config.ts` 로만 실행된다. **`npm test` 에는 포함되지 않는다.**

## 실행

```bash
npx vitest run --config vitest.qa.config.ts
```

타입컷은 검사 층위가 셋으로 나뉘어 있으니 순서대로 돌린다.

| # | 명령 | 무엇을 보나 | 개수 |
|---|---|---|---|
| 1 | `cd ../typelab-core && npm test` | **엔진이 맞는 답을 내는가** — 채점·문구·인코딩 | 40 |
| 2 | `npm test` | **웹판이 코어를 제대로 물었는가** — 배선 스모크 | 3 |
| 3 | `npx vitest run --config vitest.qa.config.ts` | **눌렀을 때 바뀌는가** — 상호작용 | 37 |

⚠️ 코어를 고쳤으면 1·2·3 **전부** 돌린다.

### `interaction.test.ts` — 검사 지점 5곳 + 전수 스윕

| 구역 | 검사 | 잡는 것 |
|---|---|---|
| 검사 대상 | 화면 파일이 제자리에 있는가 · 채점을 화면이 재구현하지 않는가 | **검사가 빈 파일을 보고 조용히 통과**하는 상태 |
| 테마 선택 | 카드가 `THEMES` 를 순회하는가 · 눌러서 `/quiz?t=<고른테마>` 로 가는가 | 어느 카드를 눌러도 같은 테스트가 열리는 결함 |
| 4문항 슬라이더 | 답이 `answers[idx]` 에 기록되는가 · 전진하는가 · 마지막에 `/result?d=` 로 가는가 · "← 이전"이 되돌리는가 | 완주율 전량 손실 · 뒤로 갔다 고치면 축이 밀리는 결함 |
| 결과 재응시 | 답·인덱스·문항이 **모두** 초기화되는가 · 재응시 링크가 이전 `?d=` 를 물고 가지 않는가 | 하나만 지워 생기는 "3/4 문항부터 시작" 상태 |
| 공유 버튼 | 복사가 클립보드에 쓰는가 · 저장이 파일을 내리는가 · 카카오가 SDK 를 부르는가 | 계측만 나가고 아무 일도 없는 공유 버튼 |
| 크로스배너 | `href` 가 데이터에서 오는가 · `preventDefault` 로 막지 않는가 | 눌러도 상대 앱으로 안 가는 죽은 배너 |
| 전수 스윕 | **모든** `<button>` 의 `onClick` 이 상태·이동·브라우저 동작 중 하나를 하는가 | 오늘 없는, **내일 생길** 죽은 버튼 |

**핵심 설계 — 한 다리 건너 일하는 핸들러를 따라간다.**
타입컷 핸들러는 대부분 `onClick={() => start(t.themeId)}` · `onClick={save}` 처럼
같은 파일의 함수를 부른다. 알콩 원본처럼 핸들러 본문만 보면 전부 "아무것도 안 하는
핸들러"로 보인다. 그래서 `effective()` 가 **호출된 로컬 함수 본문까지 최대 3단계 펼쳐서**
본다. 알콩 파일을 그대로 옮겼다면 통과만 하고 아무것도 못 잡았을 지점이다.

**한계(정직하게)** — DOM 렌더링 라이브러리가 없으므로 **소스 구조 검사**다.
실제 탭을 재현하지는 못한다. 그래도 "핸들러 본문이 무엇을 부르는가" 수준에서
드러나는 결함은 전부 잡는다.

### 가드 뮤테이션 검증 (2026-08-19)

**빨개지지 않는 검사는 가드가 아니다.** 16가지 결함을 일부러 심어 전부 빨개지는 것을 확인했다.

| 심은 결함 | 빨개진 검사 |
|---|---|
| 테마 카드가 고정 테마로 이동 | 이동 URL 에 고른 테마가 실린다 |
| 테마 카드가 계측만 하고 이동 없음 | 응시 화면으로 실제 이동한다 · 전수 스윕 |
| 답을 `push` 로 쌓음 | 답은 현재 문항 자리에 기록된다 |
| 답을 기록하지 않음 | 눈금 탭이 답을 기록한다 |
| "← 이전"이 `setIdx(0)` 만 함 | "← 이전"이 인덱스를 되돌린다 |
| 재응시 초기화에서 답만 안 지움 | 답·인덱스·문항이 모두 초기화된다 |
| 완주해도 결과로 안 감 | 마지막 탭이 결과로 보낸다 · `?d=` 가 실린다 |
| 친구 CTA 가 계측만 함 | CTA 가 실제로 이동한다 · 전수 스윕 |
| "복사됨" 표시가 안 풀림 | 눌린 티가 나고 원래대로 돌아온다 |
| 배너가 `preventDefault` 로 이동 취소 | 배너 onClick 이 이동을 막지 않는다 |
| 배너 `href` 소실 | 배너가 실제 이동 가능한 링크다 |
| 재응시 링크가 이전 `?d=` 를 물고 감 | 재응시 링크가 이전 결과를 끌고 가지 않는다 |
| 이미지 저장이 다운로드를 안 일으킴 | 이미지 저장이 실제 다운로드를 일으킨다 |
| 카카오 버튼이 SDK 를 안 부름 | 카카오 공유가 SDK 를 실제로 호출한다 |
| 계측만 하는 새 버튼 추가 | 전수 스윕 |
| 화면 파일 이름 변경 | 화면 파일이 전부 제자리에 있다 |

## 판정 기준

- **"4문항 슬라이더" 구역 실패 → 배포 불가.** 완주율이 직접 무너진다.
- **"결과 화면 재응시" 구역 실패 → 배포 불가.** 재응시가 옛 답으로 채점된다.
- "공유 버튼"·"크로스배너" 실패 → 배포는 가능하나 **바이럴·크로스 유입이 죽은 상태**다.
  같은 배포 안에서 고친다.
- "검사 대상" 구역 실패 → **다른 검사 결과를 신뢰하지 말 것.** 검사가 빈 파일을 보고 있다.
